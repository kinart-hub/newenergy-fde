## 五、本轮修掉的两个真缺陷（实测复现，不是推测）

1. **证据报告互相覆盖**：`--report` 默认同一个 `_fde_run_report.json`。追一次 `verify` 失败时，
   打开报告看到的是上一轮 `analyze` 的步骤 —— 失败证据被自己的后一次运行冲掉了。
2. **租户路径逃逸**：`tenant_root("C:/Windows/System32")` 原样返回系统目录，
   而 `reset_tenant` 会对这个返回值 `rmtree`。一列 payload 足以让"清空某个租户"变成"清空某个别的目录"。

**执行过程中自己踩到、并已修正的坑**（写下来是为了不再犯第四次）

1. **写了代码没接流程** —— 新写的 `contract._is_number` 被静态扫描当场报"定义了全库无人调用"。
   它本该承担 P1-4 的"允许范围"校验，我写漏了那一半。修法是给它真职责，不是加豁免糊过去。
2. **自我指涉（第三次）** —— 规则的正则去搜 `str(_vd) < str(_end)`，结果我自己注释里
   提到这个写法都被判违规。判据必须落在**正确调用形态**上，不要去搜错误字符串。
3. **`_block` 的 maxlen 截断** —— 长函数里调用行落在截取范围外，规则恒失败。
   恒失败看起来跟"抓到了"一模一样，很危险。改为行首锚定的全文件正则。
4. **SKIP 比 FAIL 更危险** —— 变异正则没匹配上源码的括号写法，导致该判据没被验证过。
   反向验证出现跳过就意味着这一条没验，必须查到修好为止。
5. **清单会漏未 track 的新文件** —— `gen_manifest` 原先只看 `git ls-files`，
   `lib/contract.py` 就是这样漏过一次的。改为版本控制 ∪ 文件系统并集。

## 七、复核方法

```bash
python scripts/selftest.py                       # 561 项
python scripts/fde_run.py audit                  # 46 条
python scripts/fde_run.py audit --selftest       # 96 项（0 跳过 = 每条规则都被验证过判别力）
python scripts/fde_run.py verify                 # 6 步全套
python scripts/prepublish_audit.py --strict      # 发布门槛
python scripts/static_scan.py                    # 静态 8 类
python scripts/sync_install.py --check           # 仓库与安装目录一致性
```

改任何一条规则的判据后，`audit --selftest` 必须仍然 0 跳过 —— 跳过就是"这条没验过"。
