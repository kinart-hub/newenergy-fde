## 五、本轮修掉的两个真缺陷（实测复现，不是推测）

1. **证据报告互相覆盖**：`--report` 默认同一个 `_fde_run_report.json`。追一次 `verify` 失败时，
   打开报告看到的是上一轮 `analyze` 的步骤 —— 失败证据被自己的后一次运行冲掉了。
2. **租户路径逃逸**：`tenant_root("C:/Windows/System32")` 原样返回系统目录，
   而 `reset_tenant` 会对这个返回值 `rmtree`。一列 payload 足以让"清空某个租户"变成"清空某个别的目录"。

## 六、仍未解决的风险（照实写）

- **推断边界仍会出方案**：暂时【缺受控出处 → 警告 + 要求书面确认】，没有默认阻断。
  默认一刀切会让没带规格文件的用户完全用不了；是否收紧成硬阻断需产品决策。
- **隔离写锁不完备**：仅在 `sync` 用锁，并发写同一租户文件仍可能互相覆盖。
- **8D 结案门禁不校验真实证据**：目前拦不住"证据附件为空也要结案"。
- **知识出处缺口依然存在**：127 条 params 里 0 条带出处，其中含所有 `typical_range` 与 `control` 判定阈值。补它要靠外部口径的输入，本轮无法凭空完成。

## 七、复核方法

```bash
python scripts/selftest.py                       # 423 项
python scripts/fde_run.py audit                  # 41 条
python scripts/fde_run.py audit --selftest       # 82 项（0 跳过 = 每条规则都被验证过判别力）
```

改任何一条规则的判据后，`audit --selftest` 必须仍然 0 跳过 —— 跳过就是"这条没验过"。
