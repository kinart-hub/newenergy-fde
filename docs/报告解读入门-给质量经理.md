# 报告解读入门 —— 给质量经理

> **给谁看**：质量经理 / 质量主管 / SQE。不需要懂统计，但要判断三件事——
> 这份报告**能不能拿去开会**、**能不能答复客户**、**能不能据此改工艺**。
>
> **不给谁看**：工程师版在 `SKILL.md`（参数、规则、算法细节都在那里）。
> 本文件只回答「怎么读、能做什么决定、什么情况必须停下来」。

---

## 0. 一句话先说清

**这份报告是排查工具，不是判定结论。**

它做的事：把一批数据算成「过程稳不稳 / 能力够不够 / 哪些参数在同步变化 /
最可能的原因是哪几个 / 该去现场验证什么」。

它不做的事：**判合格、判放行、下工艺指令**。这三件事必须由企业授权人员
依据受控文件确认（报告第 17 节「使用边界与责任声明」写明这一点，不是免责套话）。

理解这一条，后面所有"为什么报告写得这么谨慎"就都通了。

---

## 1. 五分钟版：只看四处

时间紧的时候，按顺序看这四处，不要从头读。

| 顺序 | 位置 | 看什么 | 一句话判断 |
|---|---|---|---|
| 1 | 报告首行 | **置信度** | 低 / 中低 → 只能内部讨论，**不能答复客户** |
| 2 | **第 1 节 结论摘要** | 有没有出现「支撑不出根因结论」 | 出现 → 候选根因只是排查方向，**不得据此改参数** |
| 3 | **第 11 节 数据缺口** | 有没有 **P0** 项 | 有 P0 → 先补数据再开会，否则结论会被推翻 |
| 4 | **第 12 节 D8 结案检查清单** | 7 个 gate 里缺几项 | 有缺项 → **不许结案**，报告本身也这么写 |

看完这四处，你已经能回答"这份东西现在能不能用"。剩下的章节是给"用什么"服务的。

---

## 2. 先看结论能不能用，再看结论是什么

报告给的置信度只有四档，且**最高只到「中高」**——
你看到有人引用本报告说"置信度 95%"，那不是这份报告的说法。

| 置信度 | 含义（报告原文口径） | 你能拿它做什么 |
|---|---|---|
| **低**（30%） | 关键维度缺失较多，结论以知识库先验为主 | 只能当"下一步查什么"的线索；不能进 8D 的 D4 |
| **中低**（50%） | 存在 1 项关键缺失，部分结论需现场确认 | 内部讨论、安排现场验证；不能答复客户 |
| **中**（60%） | 数据维度齐备但统计证据偏少 | 可以立项改善；答复客户前需补样本复算 |
| **中高**（75%） | 数据维度基本齐备，有多项统计证据支撑 | 可进 8D 草案；对外仍需 D5–D8 确审 |

**决定置信度的是「数据缺口」（第 11 节），不是「结论看起来合不合理」。**
一个听起来很像现场经验的结论，P0 缺口没补，置信度照样上不去。

## 3. 逐节对照：每节回答什么、你要做什么决定

| 章节 | 它回答什么 | 你要做的决定 | 什么情况必须停下 |
|---|---|---|---|
| **1 结论摘要** | 六句话讲完这一轮 | 要不要往下读 | 出现「支撑不出根因结论」 |
| **2 数据来源与预处理** | 这批数据是什么、多少行、哪列是时间 | 这批数据够不够代表问题区间 | 清洗后行数远少于原始行数 |
| **2b 字段适配与冲突** | 哪些列**没进**分析、为什么 | 要不要登记别名/参数 | 关键参数列被排除 |
| **2d 设备身份与解析口径** | 版式口径稳不稳 | 要不要把这台设备登记成档案 | 「未锁定口径」→ 结论会随样本浮动 |
| **3 工序判定与参数识别** | 这是哪道工序 | 判错了要重跑（`--process` 指定） | 工序判定置信度低 |
| **4 SPC 控制图与判异** | 过程稳不稳 | 先稳过程，再谈能力 | 判异点集中在某个时段 → 先查那个时段发生了什么 |
| **5 过程能力指数** | Cpk 够不够 | 要不要立项改善 | Cpk 是用**知识库典型值**算的 → 不能判合格 |
| **6 参数相关性** | 哪些参数和目标同步变化 | 缩小排查范围 | r 很高但可能混杂 → 看第 8 节 |
| **7 不良分类与 Pareto** | 不良集中在哪里 | 先打前两三项 | 样本量太少，占比不可信 |
| **8 根因定位与 5Why** | 候选根因 + 现场验证动作 | **派人去验证**，不是直接改 | 证据得分低于门槛 |
| **9 良率损失拆解** | 损失落在哪台/哪班/哪批 | 优先级排序 | 数据不完整 |
| **10 参数优化与 DOE** | 怎么试、试几组、顺序怎么排 | 要不要做 DOE | 缺受控边界 → 不出方案（这是保护，不是功能缺失） |
| **11 数据缺口与下一步** | 缺什么、补了会怎样 | 补数据 / 复算 | 有 **P0** 项 |
| **12 8D（D1–D8）** | 8D 草稿与结案检查 | 哪些能发、哪些必须人填 | D0 未填、D5–D8 未确审 |
| **13 知识沉淀候选** | 这次有哪些经验可复用 | 要不要入库 | — |
| **17 使用边界与责任声明** | 版本、文件指纹、结论分三类 | 归档时一起存 | 指纹与手上文件不一致 → 结论不是这份数据算的 |

第 17 节把结论分成 **已验证结论 / 待验证假设 / 数据限制** 三类。
向客户解释"这条能不能算数"时，直接引这一节，不要自己重新措辞。

## 4. 六个最容易导致错误决定的读法

这几条是最常见的，每一条都真实发生过。

### ① 把「候选根因」当「根因」
报告写的是**候选**，因为差异还没在现场被验证过。
D4 要的东西是「验证结论 + 验证方法」，不是「统计上最像的那个」。
正确动作：按第 8 节的 quick_checks 去现场做一次对照（改回来/换一批/换一台），
把结果填进 D4。

### ② 把 Cpk 当合格率
Cpk 1.33 对应双侧约 **63 ppm**（约十万分之六），不是"合格率 99.99%"。
更要紧的一条：**用知识库典型值算出来的 Cpk 不能判合格**。
报告第 5 节会标每个 Cpk 的规格来源，只有「企业规格书」才能用于判定；
来源是「知识库」的，报告只会写"仅作提示"。

### ③ 把控制限当规格限
- **控制限（UCL/LCL）** 是过程**自己**算出来的——过程稳定时它就在这个范围里波动；
- **规格限（USL/LSL）** 是客户/图纸**给**的。

两者可以差很远。过程很稳、Cpk 却很低，说明"稳定地做错"，这是最常见的一类现场问题。

### ④ 把相关当因果
`r = -0.96` 只说明两个数**同步变化**。可能 A 引起 B，可能 B 引起 A，
也可能两者都被第三个因素带着走（报告第 6 节的混杂检验、第 8 节的 5Why 就是干这个的）。
**同步变化不能写成"因为…导致…"。**

### ⑤ 把「没有判异」当「没有问题」
没判异有两种可能：过程真的受控，或者**样本太少/判异规则只开了基本集**，看不出来。
先看第 11 节的数据缺口、第 17 节的规则集，再决定这句话能不能说。

### ⑥ 把 8D 草稿当 8D 报告发出去
D0 未填、D5–D8 未确审时，报告自己就写着"不具备对外发出条件"。
这句话是判定，不是谦辞——客户 SQ 审 8D，最先查的就是这几项。

## 5. 报告里那些"不好看"的内容，是使用条件，不是瑕疵

报告里有四类标记，含义是固定的：

| 标记 | 含义 | 你该怎么处理 |
|---|---|---|
| **⛔ 重要提示** | 这条不满足，结论不能成立 | 停下来处理，不能跳过 |
| **⚠ 提示** | 使用条件 / 需要你知道的限制 | 读一遍，决定要不要补数据 |
| **✅ 结论** | 这一节的明确结论 | 可直接引用 |
| **ℹ 说明** | 这一节做了什么、为什么这么做 | 想追根问底时看 |

四类具体内容：

- **「　待填　」**（D0、D2、FMEA 表里常见）——留给现场填的空，不是漏了。
  填之前发出去，等于把空白交给客户填。
- **【测量系统未验证】** —— 报告里所有"差异"都建立在"测出来的数就是真值"上，
  而这条从未验证过。所以这类报告的结论**只能当排查方向**，
  不建议据此调整工艺参数或答复客户。要做 Gauge R&R 才能去掉这条。
- **某个小节写着"未产出结论 / 已降级"** —— 说明那一节算不出来（数据不够/方法不适用），
  报告会**点名**是哪一节、为什么，不会静默少一节。
- **警告清单（warnings）** —— 是这份报告的使用条件汇总，不是套话。
  转发给客户前，把每一条读一遍。

## 6. 8D 部分怎么用

第 12 节是 D1–D8 的骨架，**骨架不是成品**。

| 段落 | 系统给了什么 | 谁必须补/签 |
|---|---|---|
| **D0 应急反应** | 检查清单（ERA、三现、症状 vs 问题、样品、追溯） | 质量工程师 —— **未填则不具备对外发出条件**；ERA 时限 24 小时 |
| **D1 团队** | 角色清单 | 质量经理指定人名与日期 |
| **D2 问题描述（5W2H）** | 录入卡 + 从数据核算出的参考值 | 最先填这张卡：填完重跑一次，报告会用你填的字段**交叉校验**，冲突会逐条列出 |
| **D3 临时遏制** | 候选方向 | 生产/质量共同确认可执行性 |
| **D4 根本原因** | 候选根因 + 验证动作 | 必须补"现场验证结论"；没有验证就结不了案 |
| **D5 永久措施** | 候选方向（材料/设备/方法…） | 工艺/设备负责人确认 + 审批记录 |
| **D6 验证方案** | 判定标准、可检出差异（MDD）表、副作用观察项 | 质量工程师核对原始记录；**结果栏必须留空等现场填** |
| **D7 预防再发** | 四项动作 + PFMEA 修订要求 | 必须落到**文件编号**；只写"已培训"是退稿项 |
| **D8 结案** | 7 个 gate 的检查清单 | 7 项齐了才能结案；缺哪项会点名 |

关于 **D5–D8 四项人工确审**：这是报告强制要求的人签动作
（D5 措施已确认、D6 验证数据已核对、D7 预防已落地、D8 结案已批准）。
四项没签齐，报告会写"不得对外发出"。**这不是可以勾过去的选项。**

## 7. 术语小词典

只收报告里真的会出现的，够用就行。

| 术语 | 一句话 |
|---|---|
| **Cpk** | 过程能力：过程的波动和规格宽度的比值，扣掉了偏离中心的惩罚。越大越好，1.33 是常见门槛 |
| **Ppk** | 用整体波动算的同名指标，反映"这段时间实际做到的水平" |
| **UCL / LCL** | 控制限。过程正常波动应该落在里面，**不是规格** |
| **USL / LSL** | 规格上下限。客户/图纸给的，**不是算出来的** |
| **Nelson 规则** | 判异的 8 条经验规则（连续几点在一侧、连续上升等）。默认只开 1/2/3/5，开越多误报越多 |
| **r（相关系数）** | 两个参数同步变化的程度，-1 到 1。**不代表因果** |
| **p 值** | "如果两者其实没关系，出现这么强的结果的可能性"。越小越不像巧合 |
| **η²（eta 平方）** | 分组能解释多少波动。0.06 以上算中等，0.14 以上算强 |
| **混杂** | 两个因素总是一起变，分不清是谁的作用。报告第 8 节会专门查这个 |
| **分层** | 按设备/批次/班次拆开分别看。整体看着正常、分层后某层全不良，是常事 |
| **Gauge R&R** | 量具重复性与再现性：同一件东西反复测、换人测，结果差多少 |
| **MDD** | 最小可检出差异：这个样本量下，多大的改善才算"看得出来" |

## 8. 拿到报告后的 30 分钟（可打印）

```
□ 1. 看置信度，决定这份报告今天能用到哪一步（第 2 节那张表）
□ 2. 看第 11 节有没有 P0 缺口；有 → 先约数据，不急着开会
□ 3. 看第 4 节判异点是不是集中在某个时段/某台设备 → 是 → 先查那个时段的变更
□ 4. 看第 5 节每个 Cpk 的规格来源：企业规格书 / 知识库
□ 5. 看第 8 节：候选根因是什么、要去现场验证什么（照 quick_checks 派人）
□ 6. 看第 12 节 D0 与 D8：能不能对外发、缺哪几项证据
□ 7. 把 warnings 逐条读完，转发前确认每条都还能接受
□ 8. 第 17 节连报告一起归档（版本号 + 文件指纹）
```

第 5 条最容易拖：**候选根因不验证，后面 D5–D8 全是空转。**
一份没做现场验证的 8D，客户 SQ 一眼就能看出来。

## 10. 一句话总结

**先判断这份报告现在能不能用（置信度 + 数据缺口 + 8D 缺口），
再去用它给的方向派人验证。**
报告给你的永远是"最值得先去查的那几个方向"，不是"结论"。
方向对了，现场一天能验证完；方向错了，改参数只会把问题挪个位置。
