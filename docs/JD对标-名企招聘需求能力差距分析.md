## 三、结论：这份工具能对口哪些岗，不能对口哪些

**能直接赋能（工具产出即岗位交付物的一部分）**

- 工艺/制程工程师（PE/PTO）：SPC 趋势、DOE 方案、8D 草案、FMEA 排序、异常段剔除
- 质量工程师 / DQE（统计侧）：CPK/PPK、MSA 判定、根因候选排序、结案证据门禁
- 良率/良率分析工程师：多维关联（含 FDR 校正）、缺陷聚集、根因候选
- 可靠性工程师（统计侧）：Weibull/MTBF/B10、加速寿命拟合、RBD、可用度
- 实验室测试工程师（数据侧）：标曲/检出限/期间核查口径、质控数据统计分析

**不能替代（必须由人 + 设备 + 资质完成）**

- 仪器操作、样品制备、失效物理表征（SEM/EDS/CT/金相）
- 标准条文级符合性判定、CNAS/CMA 体系运行与评审
- APQP/PPAP 文档包的签署与客户提交
- 任何需要"签字负责"的结论

**半导体专项**（本轮补爬 长鑫/北方华创/京东方 后新增判断）：
    半导体 JD 的方法要求（SPC/MSA/FMEA/DOE/5Why/8D/CP/六西格玛）与本工具统计层**逐条对得上**，
    工序参数骨架也已补齐，所以"拿到一张 CD/Overlay/膜厚/良率 的产线数据能跑出根因候选"这一层是通的。
    但**工艺窗口、配方、机台匹配、缺陷物理表征（SEM/EDS/CT）都不在工具范围内**——
    半导体岗真正值钱的是后者。结论：**能当分析副驾，不能当工艺专家**。

**一句话**：这工具是**把数据讲清楚的引擎**，不是**实验室**，也不是**签字的人**。

## 四、风险与坑（主动标注，不等被问）

1. **知识库典型值不是规格**：所有 `typical_range` 只作量级兜底，判定必须用受控规格书。
   拿库里的典型值当判合格依据，是本工具最容易引起的误用。
2. **别名子串误命中**（已两次踩中）：给缺陷挂 `param_key` 会继承参数别名，
   `TC` 曾子串命中 `Pmax_STC(W)`，把功率列判成热导率缺陷，导致共线排除空转。
   现已在跨工序匹配上禁止继承参数别名，且新增条目脚本带**列名冲突扫描**（冲突即拒写）。
3. **B10 不是质保承诺**：失效数 <5 时工具明确拒答；即便通过，也只是统计区间，
   外推依赖"机理不变"这一前提，机理变了结论作废。
4. **加速模型选错会得到漂亮的错答案**：温度数据拿逆幂律拟合，R² 一样能到 0.99。
   所以 `--model` 必须由人指定，工具不猜。
5. **FMEA 的 S/O/D 工具不代填**：工具只做排序与矛盾检查。填 10/1/1 图省事的表，
   会被"整表复制粘贴"检测直接点名。
6. **两水平 ALT 的 R² 恒为 1**：工具会显式警告"不能作为模型可信度证据"，别拿它汇报。
