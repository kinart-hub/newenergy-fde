# 真实数据印证：用行业公开数据校验技能是否符合行业要求

> 这份文档回答一个问题：**"这工具符不符合行业要求，凭什么判断？"**
> 答案不能是"我觉得"，也不能是"仿真数据跑通了"。必须是可追溯的外部数据 + 明确的读数。

---

## 一、先划清一件事：真实数据能验什么、不能验什么

| | 能验 | 不能验 |
|---|---|---|
| **仿真数据**（`gen_enterprise_data.py`） | 判得**对不对**（有植入真值） | 真实世界的"脏"（列名匿名、NaN、截断、单位混乱） |
| **真实行业数据**（本目录） | 吃得**下吗**（健壮性）、认得**出来吗**（覆盖度）、口径**合不合**（校准） | 判得**对不对**（通常没有真值） |

所以两者不是替代关系，是**互补**。真实数据不能单独证明"判得准"——
用它证明判得准，等于把"没报错"当成"判对了"。

---

## 二、三档读数怎么解读

`scripts/realdata_check.py` 对每个用例给出三组读数：

### 1. 吃得下吗（健壮性）
- `analyze` 是否抛异常、耗时多少
- 抛异常 = **不可用**，且是最有价值的信号：说明真实数据打崩了工具

### 2. 认得出来吗（覆盖度）
- **列 → 知识库参数命中数**（`N / 总列数`）
- 一列都对不上 = 知识库是照着自洽的仿真数据写的，行业实际对不上

### 3. 口径合不合（校准）
- 真实值的量级 vs 知识库 `typical_range`
- 落在库外**不一定是错**：可能是单位不同，也可能是库里的量级兜底与实际脱节。
  两种都要人判——工具只负责把差异摆出来。

## 三、目录约定与来源铁律

```
realdata/<case>/
    data.csv        真实数据（data.* 均可）
    source.json     来源元数据（**必填**）
    truth.json      可选；有真值才算"判得对不对"
    README.md       可选
```

`source.json` 必填四项：`source_url` / `retrieved_at` / `publisher` / `caliber_note`。

**铁律**

1. **没有来源的数据一律拒收。** 一份说不清从哪来的数据，它的结论和编出来的结论在下游看起来一样。
2. **残缺数据可以用，但必须显式声明。** `truncated: true` + `truncation_note`，
   且报告里标红，不得用于统计显著性结论。
3. **完整性用 sha256 + 行列数双校验。** 只验一个不够：行数对得上但内容被改过时看不出来。
4. **不为凑数编数据。** 抓不到就写"抓不到"，这比塞一份来路不明的数据有价值。

## 四、已落地的用例（真实抓取）

| 用例 | 来源 | 规模 | 关键发现 |
|---|---|---|---|
| `secom_uci` | UCI ML Repository · SECOM（真实半导体晶圆厂） | 160 行 × 590 列（原 1567×591，**代理截断**已声明） | ①列名全匿名（X1..X590）→ **0/590 命中**：靠列名映射在真实 fab 数据上注定失败；②含 4.9% "NaN" → **打崩了 `quality_guard`**（已修）；③"Infinity" 溢出 → **打崩了图表坐标轴**（已修） |

## 五、这个回路抓出过的真实缺陷（不是演练）

| # | 缺陷 | 怎么暴露的 |
|---|---|---|
| 1 | `quality_guard._to_float` 只认小写 `"nan"`，`"NaN"` 变成 nan → `round(nan)` 抛 ValueError | SECOM 有 4.9% 单元格是 `NaN` |
| 2 | `charts._nice_ticks` 对 `inf` 做 `math.floor(log10(inf))` → OverflowError | SECOM 含 `Infinity`/`1e400` |
| 3 | `table.numeric_column` 把 inf 当有效数值下传 | 上述两者的共同上游 |
| 4 | 印证脚本自己把"analyze 崩溃"报成"仅统计可用" | 与要防的静默失真同一类，自查发现 |

前三个都是 **1055 项自检全绿也照样没抓到**的——因为仿真数据从不产生
`NaN`/`Infinity` 这种字符串。这就是真实数据的不可替代价值。

## 六、怎么用

```bash
# 跑全部用例，输出报告
python scripts/realdata_check.py --root realdata --report output/realdata_report.md

# 只跑一个
python scripts/realdata_check.py --root realdata --case secom_uci

# 严格模式（任用例来源不完整即退出码 2，可接 CI）
python scripts/realdata_check.py --root realdata --strict
```

**新增一个用例的步骤**

1. 从行业网站/论坛/公开数据集抓数据，**记录 URL 与抓取日期**；
2. 写 `source.json`（口径说明必须写清：列名含含义、单位、采样条件；匿名化也要写明）；
3. 算 sha256 填进去（`sha256sum data.csv`）；
4. 若下载不完整 → `truncated: true` + 写清残缺到什么程度；
5. 跑一遍脚本，把读数记进报告。

## 七、下一步该补什么（本轮得出的明确方向）

**0/590 命中说明的真正缺口**：真实 fab 数据是匿名列名，按名字匹配注定 0。
这不是 bug，也不是靠加别名能解决的——**匿名数据只能靠人告知列含义**。

对应补法（按优先级）：
1. **列映射访谈模板**：把 `X1..X590` 导出成待填表，让人（或 MES 元数据）填"这列是什么"；
   已有 `lib/deviceid.py` 的访谈机制可作为骨架复用。
2. **统计指纹辅助候选**：常数列 → 无信息；与良率强相关 → 候选关键参数；
   分布形态匹配 → 候选参数类别。只给**候选**，不替人定。
3. **匿名数据的降级路径要写清**：现在会走"未知工序通用模式"（只做通用统计），
   这个行为本身是对的，但要在报告里明确告诉使用者"为什么你的数据只能做这些"。
