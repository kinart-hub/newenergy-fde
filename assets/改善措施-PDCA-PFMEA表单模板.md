# 现场改善措施验证记录（PDCA / PFMEA）

> 用途：当场已验证有效的改善，用这张表把「做了什么 + 怎么验证的 + 效果多少」沉淀下来，
> 沉淀后同类问题再发生时，系统会自动优先推荐这条对策，避免每条产线重复走一遍试错。
>
> 填写后执行：
> ```
> python scripts/kb_manage.py intake --file 本文件.md --site "客户代号-产线" --by "姓名"
> python scripts/kb_manage.py review <候选编号> --approve --by "审核人"
> python scripts/kb_manage.py sync
> ```
> 字段用 `字段名：内容` 写在一行即可，脚本按此宽松解析。
>
> **提交到公开仓库前请务必脱敏**：本文件填的就是即将进入知识库的内容，
> 真实工艺设定值、内部文件编号、工程师姓名都会经由它流到下游。
> 具体红线见 `CONTRIBUTING.md`，发布前跑一遍 `python scripts/prepublish_audit.py`。
> **各企业自用的真实版本请放在 Tenant 空间**（`tenants/<站点>/knowledge/`），不要提交。

## 一、基本信息

- 缺陷类型：（填不良类型，如 针孔气泡 / 极片厚偏 / 隐裂 / 虚焊）
- 工序：（必须填 `knowledge/process_specs.json` 里 `processes` 的英文 key）
  可选：battery_coating / battery_calendering / battery_slitting /
        battery_winding / battery_filling / battery_formation / battery_grading /
        pv_wafer / pv_cell_el / pv_module_iv
- 现象：（量化描述，写清窗口内的变化，如「不良率由 X% 升至 Y%」）
- 根因参数：（对应 `params` 里的英文 key，如 oven_zone1_temp）

## 二、对策

- 改善措施：（只写动作方向，**不写具体设定值**；设定值由本工序 DOE 决定并经审批）
- 措施类型：工艺参数调整
  （可选：设备改造 / 工艺参数调整 / 来料管控 / 作业标准化 / 维保制度 / 环境控制 / 检验加严 / 原材料替换 / 其他）
- 措施细节：（务必写明「单次只变更一个变量」，否则归因不成立）

## 三、PDCA 闭环

- Plan：（提出可证伪的假设，并**先写验收判据**再动手）
- Do：（写清验证窗口：哪台设备、连续几个班次、记录什么）
- Check：（看分布不看单点：用 SPC 判异 + 前后样本对比验收）
- Act：（写入企业自有标准化文件编号，并纳入控制计划定期复核）

## 四、PFMEA 量化

- 失效模式：（填写失效模式）
- RPN(前)：（留数字）
- RPN(后)：（留数字）
  （RPN = 严重度 S × 发生度 O × 探测度 D，填写改善前后数值）

## 五、效果验证

- 验证方法：PDCA
  （可选：PDCA / PFMEA / DOE / 量产验证）
- 验证指标：（如 针孔不良率）
- 单位：（如 %）
- 改善前：（留数字）
- 改善后：（留数字）
- 样本量：（≥30 才有机会评到 A 级）
- 验证周期：（YYYY-MM-DD ~ YYYY-MM-DD）

## 六、标准化

- 标准化文件：（填你企业自己的文件编号）
- 控制计划已更新：是 / 否
- 日期：YYYY-MM-DD

## 证据分级规则（脚本自动判定，人工不能调高）

| 级别 | 判定条件 | 使用方式 |
|---|---|---|
| **A** | 定量前后对比 + 样本量 ≥30 + 已写入标准化文件；或定量验证且 RPN 降幅 ≥50% | 分析报告中直接推荐复用 |
| **B** | PDCA 四段齐全但样本量偏小；或仅有 PFMEA 记录缺闭环数据 | 推荐时标注「先小批验证」 |
| **C** | 仅经验描述，无量化、无验证方法 | 只入库，**不参与推荐** |

> 自评等级只能调低不能调高：即便填了 A，材料不足时脚本仍按实际材料降级。
> 这样做的原因很简单——知识库一旦被没有验证的"经验"污染，后面每一份报告都会被误导。
