## 版本一：GitHub Discussions 首帖（Announcement）

**标题**：`newenergy-fde v1.14.1：把检测设备导出的 CSV 变成能对外发的 8D 报告`

正文：

```
做产线数据分析的同学应该都遇到过：数据躺在 Excel 里，想看个 Cpk 得先写半小时公式，
不良率一涨就开会猜原因，8D 写到 D4 根因只能写"疑似"。

newenergy-fde 是我自己做的一套工艺数据分析技能包，现在放到 GitHub 上了。

它会做什么：
· 上传检测设备导出的 CSV/Excel（涂布、卷绕、化成、硅片、EL、组件 IV 都支持）
· 自动判定工序 → 清洗 → SPC 判异 → 过程能力 → 相关性 → 不良 Pareto
  → 根因定位 → DOE 寻优
· 直接产出工艺分析报告 + 8D 初稿（D1–D8 完整）

三条我特别在意的边界：
1. 零第三方依赖，纯 Python 标准库。企业端内网不用 pip install 就能跑。
2. 不下发任何参数设定值。D5 只给方向和类别，报告未确审时带「不得对外发出」。
3. 客户数据不入库，也不随包分发（.gitignore + 上架前隐私审计双保险）。

最快 30 秒试一下：

    git clone https://github.com/kinart-hub/newenergy-fde.git
    cd newenergy-fde
    python scripts/selftest.py        # 279 项自检
    python scripts/fde_run.py analyze -i examples/01_涂布工艺数据.csv -o output/try

许可：Elastic License 2.0（源码可得，不是 OSI 开源）。
个人和企业内部自用免费；对外提供托管服务需要单独商业授权。

如果你手上有脱敏的产线数据想试试，发给我，我出一份报告给你看效果。
```

**投稿要点**

- **先讲故事，不要先贴链接**：涂布线面密度均值稳、Cpk 不难看，但良率掉两个点；
  按设备拆开才发现一台涂布机的方差在变大，两台均值一平均就把异常抹平了
- 正文主体讲**三个坑**：不分层 / 用行业典型值当规格算 Cpk / 控制限用全段数据算
  （异常把 σ 撑大、限变宽，最该报警的点恰恰落在限内）
- 中间贴一张图（分层前后对比，或报告截图）

正文骨架（**完整版以上面的 txt 为准**）：

```
上个月帮一个朋友看他们涂布线的数据：面密度均值一直很稳，Cpk 看着也还行，
但良率就是掉了两个点。

问题出在分层——他们只看了整体 X-bar 图，没按设备分层。
两台涂布机里有一台的方差在悄悄变大，平均值互相抵消，整体看着就"正常"。

这类问题我遇到过太多次，于是把自己常用的分析流程写成了一套脚本，
现在开源放在 GitHub 上：上传检测设备导出的 CSV/Excel，
自动做完工序判定 → 清洗 → SPC 判异 → 过程能力 → 相关性 → Pareto → 根因 → DOE，
直接产出能进 8D 的报告。

（中间贴：一张分层前后的对比图 / 报告截图）

几个设计上的取舍，可能有争议，欢迎讨论：
· 零第三方依赖：不用 pandas/numpy。原因是企业端内网装包是真实成本，
  而不是我不会用。
· 不下发参数设定值：D5 只给方向和类别。AI 越权改工艺参数是灾难，
  这条必须写死在代码里。
· 未确审不得对外：D5–D8 没经人工确审，报告头部带红标。
  这不是功能没做完，是刻意的设计。

想试的话：`git clone ... && python scripts/selftest.py`（279 项自检）。
有脱敏数据想让我跑一遍的，评论区或私信都行。
```
