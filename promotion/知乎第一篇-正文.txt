1. Cpk 看着挺好，良率却在掉——问题出在"分层"
2. 产线数据躺在 Excel 里没人分析？我写了个脚本，上传就出 8D 初稿
3. 为什么我坚持这个分析工具零第三方依赖

—————————————— 正文 ——————————————

上个月帮一个做涂布的朋友看数据：面密度均值一直很稳，Cpk 算出来也不难看，
但良率就是掉了两个点。会上谁都说不清为什么。

我把数据按设备拆开看了一眼，原因就很直白了：两台涂布机里，有一台的方差在
悄悄变大。两台的均值一个偏高一个偏低，合起来一平均，整体看着"正常"，
整体 Cpk 也"还行"。异常被平均掉了。

这不是个例。产线数据有三个坑，都会让人得出"看起来一切正常"的结论。

第一个坑：不分层。
设备、批次、班次、卷针号，任何一个维度里藏着一个跑偏的水平，
整体统计都会把它抹平。先分层再统计，顺序反了就什么都看不出来。

第二个坑：用行业典型值当规格算 Cpk。
Cpk 是相对规格算的。用企业自己的规格书算，和用行业典型值算，
数字可能差不多，效力完全不同。前者能拿去给客户看，后者只能内部参考。
我的做法是：没拿到企业规格，就在报告里明写"用的是行业典型值，不得用于客户报告"，
绝不让你拿一个没效力的数字去对外。

第三个坑：控制限用全段数据算。
这是最隐蔽的一个。如果这段数据里本身就有异常点，异常会把标准差撑大，
控制限跟着变宽——结果就是最该报警的那个点，恰恰落在限内。
正确做法是先建立稳定基线（只用稳定期的数据建限），再用它去判后续。
异常点超过四分之一时，应该如实判"未建立稳定基线"，而不是硬算一个数字出来。

这三个坑有个共同点：它们都不会报错，只会让你得出一个错误的、但看起来很专业的结论。

我这些年把这些流程攒成了一套脚本，最近整理好放出来了：
上传检测设备导出的 CSV/Excel，它自动做完工序判定、清洗、SPC 判异、
过程能力、相关性、不良 Pareto、根因定位、DOE 寻优，
最后产出一份工艺分析报告和一份 8D 初稿（D1 到 D8 是完整的）。

三个设计上的取舍，可能有点非主流，说一下理由：

一是零第三方依赖，不用 pandas 也不用 numpy，纯 Python 标准库。
不是我不会用，是企业内网装包是真实的成本。我见过太多"分析方案很好，
但客户机器上装不上"的情况。这套东西拷过去双击就能跑，数据也不出厂。

二是它不下发任何参数设定值。D5 那一步只给方向和类别，不给具体数值。
AI 越权去改工艺参数是灾难，这条必须写死在代码里，不能靠提示词约束。

三是没确审就不许对外。D5 到 D8 没经过人工逐项核对签字，
报告头部会带一条"不得对外发出"的标记。这不是功能没做完，是刻意的设计——
8D 是要发出去给客户看的，写得太像结论，就会有人直接发出去。

想试的话，两条命令：

git clone https://github.com/kinart-hub/newenergy-fde.git
cd newenergy-fde && python scripts/selftest.py

279 项自检跑完应该全绿，再用 examples 里的示例数据跑一遍就有报告。
不需要 pip install 任何东西。
