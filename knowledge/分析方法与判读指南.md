# 分析方法与判读指南

> 本文件定义"怎么分析"。脚本负责算，本文件负责**判读与避坑**。
> 无论脚本算出什么，都必须经过本文的复核逻辑才能写进结论。

---

## 1. SPC 判异规则（Nelson 1-8，含 Western Electric 4 条）

| 规则 | 描述 | 典型物理含义 | 现场动作 |
|---|---|---|---|
| 1 | 1 点超出 ±3σ | 突发特殊原因 | 立即停机/隔离，查变更记录 |
| 2 | 连续 9 点在同侧 | 均值偏移 | 查换料、换刀、参数调整、换班 |
| 3 | 连续 6 点单调升降 | 趋势漂移 | 查磨损、沉降、老化、季节温湿度 |
| 4 | 连续 14 点上下交替 | 系统性振荡 | 查过度调整（人员频繁干预）、周期性干扰 |
| 5 | 连续 3 点中 2 点在 A 区（>2σ） | 较大特殊原因 | 查近期变更 |
| 6 | 连续 5 点中 4 点在 B 区外（>1σ） | 中等偏移 | 规则 2 的早期预警 |
| 7 | 连续 15 点全在 C 区（<1σ） | 数据分层或控制限过宽 | **检查是否混入多批次/多设备数据未分组** |
| 8 | 连续 8 点两侧且都不在 C 区 | 双峰混合分布 | **检查是否两台设备/两个供应商/两个配方混在一起** |

### 判读要点（容易误判的地方）

- **规则 7 触发 ≠ 过程变好**。它通常意味着你把一个混合样本当成单一过程在看，
  正确的动作是**先分层（按设备/批次/班次）再重画控制图**。
- **规则 8 是"数据混批"的强信号**。看到它，第一动作是查数据来源是否混合，
  而不是去调工艺。
- **规则 1 触发后不要急着调机**。先确认是真实异常还是测量/录入错误
  （传感器跳变、人工输入错误在产线数据中很常见）。
- 单值图（X-MR）的 σ 用 MR/d2 估计，**对趋势不敏感**。
  有明显趋势的数据用 X-MR 会低估 σ，应改用 EWMA 或对差分序列作图。

## 2. 过程能力指数

| 指标 | 含义 | 使用场景 |
|---|---|---|
| Cp | 规格带宽度 / 过程宽度（居中度无关） | 看"过程的潜在能力" |
| **Cpk** | 考虑偏移后的能力 | **量产判定的主指标** |
| Pp / Ppk | 用整体标准差（含组间波动） | 看"长期实际表现" |
| Cpm | 考虑偏离目标值的损失 | 目标值明确时 |

| Cpk | 分级 | 处置 |
|---|---|---|
| ≥1.67 | A（充足） | 可考虑放宽检验频次 |
| 1.33-1.67 | B（满足） | 量产可接受，维持监控 |
| 1.00-1.33 | C（不足） | 需改进，加严检验 |
| <1.00 | D（严重不足） | 必须整改，考虑 100% 检验 |

### 三个必须核对的前提

1. **过程必须处于统计受控状态**，Cpk 才有意义。
   过程失控时算 Cpk 等于给一堆混合物算平均——数值好看但没有预测价值。
2. **数据必须近似正态**（或做正态变换）。
   严重偏态数据用正态假设算 ppm 会严重低估尾部风险。
3. **规格必须来自受控文件**。用行业典型值算出的 Cpk 只能用于内部参考，
   **不能写进给客户的报告**。

### Cpk 与 ppm 的对应（含 1.5σ 漂移的行业惯例）

| Cpk | σ 水平 | ppm |
|---|---|---|
| 0.33 | 2.0 | 308,537 |
| 0.67 | 3.0 | 66,807 |
| 1.00 | 4.0 | 6,210 |
| 1.33 | 4.5 | 1,350 |
| 1.67 | 5.0 | 233 |
| 2.00 | 6.0 | 3.4 |

## 3. 相关性分析：四个必须避开的陷阱

### 陷阱 1：相关 ≠ 因果
涂布速度与面密度强相关，不代表是速度"导致"面密度变化——
可能是同一台泵的供料特性同时决定了两者。
**处置**：相关性只用于**排序候选**，确认必须靠机理 + 现场单因子验证。

### 陷阱 2：辛普森悖论（分层反转）
整体看 A 与 B 正相关，按设备分层后每台设备内都是负相关。
**处置**：先看分组 ANOVA，再决定是做整体相关还是分层相关。

### 陷阱 3：多重共线性
两个参数高度相关（|r|>0.7 或 VIF>5）时，不能同时作为独立因子进入 DOE，
否则效应会被错误分配。
**处置**：看 VIF 表，VIF>5 的因子二选一。

### 陷阱 4：样本量与 p 值的误读
- n 很大时（产线数据动辄上千行），**微小的 r 也会显著**（p<0.05）。
  此时要看**效应量（r 或 η²）**，不是 p 值。
- n 很小时（<8），再大的 r 也不可信。
**判读规则**：|r| < 0.3 视为弱相关，即使 p 显著也不应作为整改依据。

### 滞后相关的正确用法
上游参数变化**领先**下游指标变化，是"因果传导"的有力证据。
- 滞后 0 最强 → 同步变化，可能同源
- 滞后 k>0 最强 → 参数先动、指标后动，符合传导特征
但注意：**滞后相关需要时间戳精确对齐**，粒度太粗（只有日期）时结论不可靠。

## 4. DOE 选择指南

| 场景 | 推荐设计 | 试验次数 | 可估内容 |
|---|---|---|---|
| 因子多（≥5）、只找主因 | L8/L16 正交表 | 8 / 16 | 主效应（交互混杂） |
| 因子少（≤4）、要看交互 | 全因子 2^k | 4-16 | 全部交互 |
| 要找最优点 | Box-Behnken / CCD | 15-20（3 因子） | 二次响应面 |
| 三水平、看非线性 | L9 / L27 | 9 / 27 | 含曲率 |

### 执行要点（决定成败的细节）

1. **随机化运行顺序**，抵消时间漂移（温度、浆料沉降、设备热机）
2. **每号至少 3 次重复**，用于估计纯误差
3. **响应优先用连续量**（容量、内阻、功率、TTV），
   **避免只用 OK/NG**——二值响应会把信息量砍掉一大半
4. **水平跨度要够大**：跨度太小效应被噪声淹没；
   跨度太大会引入非线性，甚至超出安全窗口
5. **因子水平取值依据**：脚本默认用当前数据的 P10/P90 外扩 15%，
   但这个取值必须经工艺工程师复核安全性后再执行

### 主效应图的读法
- 折线**陡** → 该因子影响大
- 折线**平** → 该因子在设定范围内不敏感（可以放宽控制，降低成本）
- 折线**交叉**（交互作用显著）→ 两因子不能单独设定，必须联合优化

## 5. 根因定位方法论

### 5.1 双证据链融合（本 Skill 的核心设计）

```
知识库先验（机理）  0.35      数据证据（统计）  0.40
时序吻合度          0.15      可验证性          0.10
                    ↓
              综合得分排序 → 候选根因
```

**为什么不能只用统计？**
产线数据里，最相关的参数常常不是根因——它可能只是与真正的根因同步波动的伴随变量。
知识库先验能把它压下去。

**为什么不能只用知识库？**
同一现象在不同企业的根因分布不同（设备、来料、管理水平差异）。
数据证据能把通用先验修正到本厂实际。

### 5.2 分层优先原则

拿到任何不良数据，**第一动作永远是分层**，不是算相关性：

```
按设备号分层 → 集中在单台？→ 设备问题（查保养、刀具、参数）
按批次分层   → 集中在单批？→ 来料问题（查供应商、检验记录）
按班次分层   → 集中在单班？→ 操作问题（查作业指导、培训、人员）
按时间分层   → 集中在某段？→ 变更问题（查工程变更、维修、换型）
都分散       → 系统性问题（查设计窗口、规格合理性）
```

**这条原则的价值**：分层能在 5 分钟内把问题边界收窄一个数量级，
比跑复杂模型有效得多。

### 5.3 5Why 的正确写法

- 每一层的"因为"必须有**可验证的证据**，不能是推测
- 第 4、5 层通常涉及**为什么没被发现/没被拦截**（控制计划、检测点布局）
- **脚本只给到方向，第 4-5 层必须由现场工程师确认**
  代填 5Why 在客户审核时是直接失分项

## 6. 良率损失拆解

### 拆解顺序

1. **Pareto 定主因**：A 类（累计 80%）优先整改
2. **分层定位置**：A 类不良集中在哪台设备/哪个批次
3. **时间定起点**：不良率什么时候开始抬升（与什么变更同步）
4. **量化损失**：不良数 × 单位成本 / 单位工时

### 必坑

- **比率不能直接相加**：各班次不良率求平均是错的，必须用产量加权
- **没有产量列时**：用"超出基线的累计偏差"代替，并在报告中注明是替代口径
- **连续测量列不能当缺陷计数求和**：
  例如「极片错位」是 0.28 mm 这种连续量，求和没有物理意义

## 7. 结论置信度规则

| 缺口情况 | 置信度 | 使用限制 |
|---|---|---|
| P0 缺失 ≥2 项 | 低（0.3） | 仅作方向参考，必须现场验证 |
| P0 缺失 1 项 | 中低（0.5） | 部分结论需确认 |
| 维度齐备但证据少 | 中（0.6） | 建议补充样本后复算 |
| 维度齐备 + ≥3 项显著证据 | 中高（0.75） | 可用于内部决策 |

**硬约束**：置信度为"低/中低"时，结论**不得直接作为客户 8D 的 D4 根因结论**。

### P0/P1/P2 分级

| 级别 | 内容 | 缺失后果 |
|---|---|---|
| **P0 必需** | 时间戳、被分析指标、分组维度 | 无法定位，结论不可用 |
| **P1 重要** | 工艺参数实测值、规格上下限、来料批次 | 影响根因精度与 Cpk 有效性 |
| **P2 增强** | 历史基线（≥30 点）、解剖结果、环境记录、保养记录 | 影响量化与验证 |

## 8. 报告规范

### 必含要素
1. **数据来源与样本量**（可追溯）
2. **规格来源说明**（企业规格 or 行业典型值 → 影响结论效力）
3. **置信度**（必须显式标注）
4. **数据缺口清单**（P0/P1/P2）
5. **结论与建议动作分离**（结论是事实，建议是判断）

### 禁止写法
- ~~"建议加强过程控制"~~ → 具体写"将 X 参数抽检频次从 1次/2h 提到 1次/30min"
- ~~"疑似浆料问题"~~ → 写"固含与面密度 r=-0.96（p<0.001），
  建议先做固含单因子验证：保持其他参数不变，固含回调至 52±0.5% 观察 2 个班次"
- ~~"需进一步分析"~~ → 写"需补充 X 数据（P0），补充后可区分 A 与 B 两种根因"

### 对外报告（客户 8D）的红线
1. D2 必须补齐 5W2H
2. D4 根因必须有**数据 + 机理 + 现场验证**三重支撑
3. D5 永久对策必须能验证有效性（有量化验收标准）
4. D7 预防措施要落到控制计划（Control Plan）与作业指导书的变更

## 附录：现场补充判读经验（脚本自动累积）

本附录由 `kb_manage.py sync` 按登记时间顺序自动追加，勿手工编辑其中的条目编号行。

### 判异优先查设备，再看物料批次

- 条目编号：`C20261010-007`｜强度：建议｜登记：2026-10-10｜来源：工艺工程基线
- 适用场景：SPC X-MR / Xbar-R 图出现连续同侧、趋势或周期

出现 Nelson 判异时，先做设备/班次/通道分层（参见报告第 9 节的 η²）。只有当差异在设备间不聚集（η²<0.06 且不显著）时，才把方向转向来料批次。顺序反了会付出大量无效的来料追溯工时，这也是最常见的误判路线。

> 易错点：看到所有设备同步漂移就直接判定为来料问题，其实很可能是共用公用工程（烘箱蒸汽、车间空调、压缩气）在漂移，应先排查共用源。

### Cpk 不足先拆分 σ 与均值偏移，不要直接调机

- 条目编号：`C20261010-008`｜强度：强制｜登记：2026-10-10｜来源：工艺工程基线
- 适用场景：过程能力 Cpk < 1.33 且需提出改善方向时

Cpk = min(Cpu, Cpl)，同时受离散 σ 和均值偏移影响。先看 Pp 与 Cpk 的差距：Pp 高而 Cpk 低说明只是中心没对准（调设定值即可，成本低）；Pp 本身低说明离散大（要查设备、来料一致性、测量系统）。不拆分就调参数，往往把已经对准的中心调偏。

> 易错点：忽视测量系统：GR&R > 30% 时 σ 里有一大块是量具噪声，此时任何过程改善动作都可能是在追测不准的数。

### 相关不等于因果：必须先做时间对齐

- 条目编号：`C20261010-009`｜强度：强制｜登记：2026-10-10｜来源：工艺工程基线
- 适用场景：参数相关性矩阵出现 |r| ≥ 0.6 的强相关对

产线上大量参数由同一条主令链驱动（例如提速会同时抬高温度、张力、风量），它们成对同向变化，形成高相关但没有因果的伴随关系。判定因果必须同时满足：① 参数变化时刻早于指标变化（做滞后相关）；② 存在可解释的物理机理；③ 单因子验证能复现。三条缺一条只能写「疑似相关」，不能写根因。

> 易错点：把结果指标当根因。典型例子：面密度与不良率常常强相关，但面密度是被固含、泵速、车速决定的结果，去优化它等于在调现象。

### 清洗时务必保留异常点：异常点往往就是线索

- 条目编号：`C20261010-010`｜强度：强制｜登记：2026-10-10｜来源：工艺工程基线
- 适用场景：预处理阶段的异常值处理

本系统对异常值只标记不删除。在工艺诊断里，被统计判为异常的点经常就是故障窗口本身，删除它们会把真正要找的信号抹掉。只有在确认是录入错误（缺测占位 -9999、单位写错、设备通讯丢包）时才允许剔除。

> 易错点：用 3σ 规则剔除异常后再算 σ，会得到人为收紧的控制限，后续任何点都更容易看起来失控。稳健统计应当用 MAD，而不是反复删点。
